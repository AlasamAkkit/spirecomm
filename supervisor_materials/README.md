# Supervisor review — C2 human feedback

The Slay the Spire FYP's authoritative human teaching is not in model weights.
It is maintained as a local raw-memory source, a derived playbook, and a
human review bank. These live files must not be committed directly.

## Already available — verified historical feedback through Run 37

This directory contains static publication copies reconstructed from the
tracked, frozen Run-38-pre-A10 archive (whose feedback/playbook were finalized
through Run **37**). They include 29 HUMAN_TEACHING decisions and 8
APPROVE_INITIAL decisions:

- c2_human_feedback_through_run37.md — readable supervisor review;
- c2_human_feedback_through_run37.json — structured, verbatim data.

These **do not** include Runs 38–56. For a complete current snapshot,
follow the export instructions below using the live local files and publish
the separately named through-Run-56 files after reviewing them.

## What can be shared

A static supervisor snapshot is generated by the read-only exporter:

    reflection/export_c2_supervisor_feedback.py

When the local finalized memory is updated through Run 56, from the repository
root (the directory that contains reflection/ and spirecomm/), run:

    & .\spirecomm\venv\Scripts\python.exe .\reflection\test_export_c2_supervisor_feedback.py
    & .\spirecomm\venv\Scripts\python.exe .\reflection\export_c2_supervisor_feedback.py --through-run 56 --validate-only
    & .\spirecomm\venv\Scripts\python.exe .\reflection\export_c2_supervisor_feedback.py --through-run 56

The output will be:

    supervisor_materials/c2_human_feedback_through_run56.md
    supervisor_materials/c2_human_feedback_through_run56.json

The Markdown version is designed for a supervisor to read. The JSON version
preserves the exact human-authored feedback text and relevant review metadata
in a simple, analysis-friendly format. The exporter also includes additional
authoritative targeted corrections from raw memory, which are distinct from
the original human review entry.

The exporter does not include:
- human-computer local file paths or user IDs;
- full trajectories, runtime log streams, or LLM prompt/response histories;
- generated model reflections not separately approved as direct teaching;
- API credentials, local checkpoints, mutable playbook state, or raw feedback
  bank metadata.

## Before publication

Open both generated files and verify the contents are appropriate for the
intended supervisor audience. The exporter fails if it detects common
credential/local-path patterns, but this is not a complete sensitive-data
scanner. A GitHub push exposes committed files according to the repository's
visibility and access rules. Files removed in a later commit remain in Git
history; review BEFORE committing.

After approval, commit only the generated publication copies:

    git status --short
    git add -- supervisor_materials/c2_human_feedback_through_run56.md supervisor_materials/c2_human_feedback_through_run56.json
    git diff --cached --stat
    git diff --cached --check
    git commit -m "docs(fyp): supervisor review of C2 human feedback through Run 56"
    git push origin master

Never use git add -f on the active condition_c2_* files. Do not commit
reflection/condition_c2_outputs, the Run 57 interrupted evidence,
spirecomm/run_events_c2.jsonl, or local-only checkpoints.

## Reading and interpretation

- HUMAN_TEACHING means the researcher replaced the initial LLM reflection
  with direct human instruction; the text in the snapshot is verbatim.
- APPROVE_INITIAL means the researcher approved the existing model-generated
  reflection. There is no new run-level human-written lesson to reproduce;
  the snapshot records the decision only.
- Additional authoritative corrections come from human responses to
  post-run targeted questions, preserved in the raw-memory file.
- The raw-memory and playbook rules are different: the snapshot is a review
  of human feedback, not evidence of whether that feedback was retrieved,
  followed, or improved later gameplay.

The static snapshot has a numbered upper boundary (Run 56). Run 57 originally
stopped because of malformed JSON and is a separately recorded incomplete
attempt; do not publish it as a completed or reviewed run. To include later
completed/finalized runs, rerun the exporter with a new through-run value and
commit the separately named output files. Do not rewrite older snapshots.
